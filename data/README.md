# Data

Everything the app shows comes from the YAML files in this folder. `npm run data`
(run automatically by `dev`, `build`, `check` and `test`) validates them and writes
the JSON the app loads to `src/generated/` (git-ignored).

```
data/
  shared/                 # data shared by every Mystery Dungeon game
    types.yaml            # type ids
    species.yaml          # species ids, National Dex number, what each evolves from
    portrait-credits.yaml # portrait artists per species or form (generated by `npm run portraits`)
  games/<gameId>/         # one folder per game (only `dx` for now)
    game.yaml             # metadata, recruit methods and page sections, id aliases
    pokemon.yaml          # checklist entries
    dungeons.yaml         # dungeons, in unlock order
    camps.yaml            # Rescue Team Camps / Friend Areas, in unlock order
  locales/<lang>/         # display names, one folder per language
    shared.yaml           # names shared by every game (species, types)
    <gameId>.yaml         # names for one game; overrides shared.yaml
```

## Ids vs names

Data files only use **ids** (`mt-steel`, `farfetchd`). Every visible name lives in
`locales/`, keyed by `<kind>.<id>` (`dungeon.mt-steel`, `species.farfetchd`). That way:

- A name can change between games (a move or item renamed in a later game) by
  overriding it in `locales/<lang>/<gameId>.yaml`, without touching shared data.
- Translations are separate files; a missing translation falls back to English.
- Fixing a typo in a name never breaks anyone's saved progress.

Ids are permanent once published: saved progress is keyed by entry id. If one really
has to change, add `old-id: new-id` to `idAliases` in `game.yaml`.

New kinds (`move`, `item`, ...) need no code changes in the locale files: add a
`move:` section and reference `move.<id>` from the app.

## Adding a language

1. Copy `locales/en/` to `locales/<lang>/` and translate the values (partial is fine).
   Use the official names from the games, not your own translation: the wiki for that
   language (e.g. WikiDex for Spanish) or Bulbapedia's "In other languages" tables.
   Watch out for names a remake changed (DX renamed several places), and remember that
   game terms are translated too (Spanish calls dungeons "territorios").
2. If a whole kind keeps its English names (Pokémon names in Spanish), write
   `species: english` instead of copying them. Otherwise the build warns about every
   name that falls back to English.
3. Add the UI strings in `src/i18n/ui/<lang>.ts` and register the language in
   `src/i18n/locales.ts`. A test checks that every string and `{param}` is there.

## Adding a game

1. Create `games/<gameId>/` with the same files as `dx`, and `locales/en/<gameId>.yaml`.
2. Register the game in `src/games/registry.ts`.

Saved progress is already stored per game (`game/<gameId>/progress`), and routes are
prefixed with the game id (`#/dx/...`), so games never collide.

## Sources

The initial DX roster (types, camps, recruit locations) was imported from
[Serebii](https://www.serebii.net/dungeonrescueteamdx/pokemon.shtml) and the dungeon
list from [Bulbapedia](https://bulbapedia.bulbagarden.net/wiki/Pok%C3%A9mon_Mystery_Dungeon:_Rescue_Team_DX).
It has not been verified entry by entry in-game.

Artwork (`public/camps/<gameId>/<camp-id>.webp`, `public/dungeons/<gameId>/<dungeon-id>.webp`)
and the camp and dungeon order come from Serebii's
[camp](https://www.serebii.net/dungeonrescueteamdx/rescueteamcamp.shtml) and
[dungeon](https://www.serebii.net/dungeonrescueteamdx/dungeon/) lists. Run `npm run artwork`
(needs `cwebp`) after adding a camp or dungeon; it also warns if `camps.yaml` or `dungeons.yaml`
is out of Serebii's order. One without artwork shows a "?" placeholder; mark it `artwork: false`
in the YAML when Serebii has none (Rock Path and Snow Path), so the build doesn't warn.

`evolvesFrom` in `shared/species.yaml` comes from PokéAPI's `pokemon_species.csv`.

Each entry's `evolve` (level and/or Evolution Crystals) comes from the evolution chain on
Serebii's per-Pokémon DX pages (`/dungeonrescueteamdx/pokemon/<dex>.shtml`). Serebii leaves
Bellossom, Politoed and Gallade blank and shows a mainline friendship icon for Crobat; those
four use the rule from its [evolution page](https://www.serebii.net/dungeonrescueteamdx/evolution.shtml)
(stone or friendship evolutions take 2 crystals from a base form, 4 from a stage 1).

Floors, level and base recruit rate for every `obtain` entry, and the whole `fainted` list,
come from the Rescue Team DX tables on Bulbapedia's dungeon pages (Rock Path and Illusory Grotto
have none). Where Serebii and Bulbapedia disagreed on which Pokémon appear in a dungeon (a
handful of rows), we follow Bulbapedia.

Mystery House dungeons come from Bulbapedia's [Mystery House](https://bulbapedia.bulbagarden.net/wiki/Mystery_House)
pools. Serebii also lists a Mystery House for 22 evolved Pokémon that are in none of those pools
(Ivysaur, Venusaur...), apparently as a generic label for Pokémon that can't be recruited in a
dungeon; we follow Bulbapedia and leave them out.

Spanish names come from [WikiDex](https://www.wikidex.net/) (which marks the GBA and DX
names separately) and were cross-checked with Bulbapedia, which agrees on every dungeon.
For camps Bulbapedia sometimes gives only the GBA name. One real disagreement: Southern
Island is "Isla Sureña" on WikiDex and "Isla del Sur" on Bulbapedia (we use WikiDex). Known gap: Celebi's strong-foe
dungeon was missing from the source and was left out.
